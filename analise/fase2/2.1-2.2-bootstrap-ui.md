## Relevância para o LeccorCut (resumo)

1. **Separar processos por risco**: o CapCut isola sondas de GPU (`ttdaemon`), benchmark (`taskcontainer`), renderer web (CEF) e agente de IA (Bun + sandbox VM) — o editor Qt sobrevive a falhas de driver. Modelo replicável com `QProcess` + arquivo de resultado.
2. **Bridge web ↔ nativo por nome de método**: `callType` → método do `QMetaObject` é um padrão simples para expor um `QObject` à web (no LeccorCut, equivalente a `QWebChannel` ou a um roteador JSON próprio).
3. **Preview de vídeo em página web sem codificar**: frames do motor nativo vão por memória compartilhada/textura GPU e um Chromium modificado os consome — caro de reproduzir; para o LeccorCut, manter o preview no Qt e usar web só para painéis.
4. **Contrato de versão entre nativo e front** (`productHostApi` min/max + hashes SHA-256 no `web-manifest.json`) é uma prática barata e útil.
